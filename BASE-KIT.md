# Базовая комплектация dev-контейнера

Что гарантированно есть в каждом контейнере, поднятом через `cdev` (Ctrl-N), и почему.
Меняешь состав — меняй `Dockerfile` и раздел «Что установлено» в `CLAUDE.md.template`,
иначе Claude будет искать то, чего нет, или не знать о том, что есть.

## Что внутри

### Рантаймы
| Что | Зачем |
|---|---|
| Node 22 + npm | база образа; на нём же работает Claude Code |
| Python 3.11 + pip + venv | без pip/venv питон в контейнере наполовину бесполезен |
| build-essential | нативные модули npm/pip без него не собираются |

Языки под конкретный проект (Go, Rust, Java) намеренно **не** ставим: это десятки
мегабайт ради одного проекта. Нужен постоянно — добавляй в `Dockerfile`, разово — ставь
в пользовательское окружение.

### Git и GitHub
| Что | Зачем |
|---|---|
| git | идентичность настраивается в образе, ключ засевается при создании |
| `gh` | приватные репозитории, PR, issues — без него Claude слеп к GitHub |

### Работа с кодом
`ripgrep` (`rg`), `fd`, `jq`, `yq`, `tree`, `less`, `vim-tiny`, `shellcheck`.

`shellcheck` тут не для красоты: ralphex-планы для инфраструктурных проектов используют
его как проверочный гейт, а гейт, которого нет в контейнере, останавливает цикл.

`yq` — бинарь mikefarah, не одноимённый пакет Debian (тот другой инструмент).

### Инфраструктура
| Что | Зачем |
|---|---|
| `docker` + `docker compose` | **без демона**, `DOCKER_HOST=ssh://deployer@192.168.0.100` |
| `arcane` | обёртка над Arcane API (проекты, compose, передеплой) |
| ssh, rsync | доступ на хост, перенос файлов |

⚠️ **`docker` здесь = сервер.** Локального демона в контейнере нет, все команды уходят на
OMV по SSH. `docker ps` показывает прод, `docker rm` его же и удалит. Правила обращения
описаны в `CLAUDE.md.template`; это осознанный размен удобства на близость к проду.

Обёртка `arcane` берёт на себя только то, чего docker CLI не умеет — проекты (стеки):
их список, compose, `.env`, up/down/redeploy. Контейнеры (`ps`, `logs`, `restart`) она
проксирует в тот же docker, чтобы не было двух разных ответов на один вопрос.

### Базы и диагностика
`psql`, `sqlite3`, `redis-cli` — отладка test-баз на сервере напрямую, без цепочки
`ssh omv docker exec …`. `dig`, `ping`, `nc`, `htop`, `procps` — сетевая диагностика.

### Автономная работа
`ralphex` (ставится из GitHub-релизов с проверкой контрольной суммы) и `tmux`.

`codex` (npm-пакет `@openai/codex`) — внешний ревьюер в цикле ralphex: план выполняет
Claude Code, а результат перечитывает другая модель. Без него фазу внешнего ревью
приходится отключать, и цикл остаётся с самопроверкой одной моделью — сигнал заметно
слабее. Ставим его от root в `/usr/local`, в отличие от `claude`: codex не пытается
обновлять сам себя, поэтому root-owned каталог ему не мешает.

## Что засевается при создании контейнера

Не в образе, а раскладывается `claude-dev-ctl` при `deploy` (и чинится при `retrofit`) —
потому что это секреты и настройки, которым нельзя лежать в слоях образа:

| Что | Куда | Источник на хосте |
|---|---|---|
| ключ входа с Mac | `~/.ssh/authorized_keys` | `mac_authorized_key` |
| ключ на OMV-хост (deployer) | `~/.ssh/id_ed25519` | `keys/id_dev_to_omv` |
| ключ GitHub | `~/.ssh/id_github` | `keys/id_github` |
| `~/.ssh/config` | алиасы `omv`, IP хоста, `github.com` | генерируется |
| долгоживущий токен Claude | `~/.claude_env` (env `CLAUDE_CODE_OAUTH_TOKEN`) | `claude-oauth-token` |
| копия сессионного токена | `~/.claude/.credentials.json` | `claude-credentials.json` (запасной путь) |
| опознание аккаунта Claude | ключи в `~/.claude.json` | `claude-account.json` |
| токен Arcane | `~/.arcane_token` | `arcane_container_token` |
| креды codex | `~/.codex/auth.json` | `codex-auth.json` (один раз) |
| настройки codex | `~/.codex/config.toml` | `codex-config.toml.template` (один раз) |
| настройки ralphex | `~/.config/ralphex/config` | `ralphex-config.template` (один раз) |
| правила для Claude | `~/.claude/CLAUDE.md` | `CLAUDE.md.template` |
| скиллы Claude Code | `~/.claude/skills/` | `skills/` |

Логин Claude переносится **долгоживущим токеном** (`claude setup-token`), а не копией
сессионных кред. Копия работает лишь до первого обновления: refresh-токены ротируются, и
контейнер, обновившийся первым, обесценивает копию у всех остальных — включая мастер на
хосте. Пока скопированный access-токен жив, всё выглядит рабочим, а ломается ровно в тот
момент, когда понадобится обновление. Копирование оставлено запасным путём с честным
предупреждением при `deploy`.

Копия, если до неё дошло, — это **два** файла, и одного мало. Токен в
`~/.claude/.credentials.json`, опознание аккаунта (`oauthAccount`, `userID`, отметка о
пройденном онбординге) — в `~/.claude.json`. Без второго Claude уходит во вход, хотя
валидный токен лежит рядом. `claude-dev-ctl save-creds` снимает обе половины разом —
снимать их порознь значит однажды забыть про вторую.

Что переживает пересоздание контейнера: тома `/workspace`, `~/.claude`, `~/.codex`,
`~/.config` (настройки ralphex, авторизация `gh`) и `~/.ssh`. Всё остальное в `$HOME`
живёт в слое контейнера и умирает вместе с ним; единственное исключение —
`~/.claude.json` с отметками о доверенных каталогах: `rm` снимает его в `state/`, а
`deploy` кладёт обратно.

Помеченное «один раз» засевается только при создании контейнера. В настройках codex и
ralphex живут решения пользователя — доверенные каталоги, выбранная песочница, — и
`retrofit` их намеренно не трогает: молча стереть их значит сломать рабочий контейнер.
Креды codex не перезаписываются по другой причине: токен в контейнере обновляется сам и
бывает свежее мастера на хосте. Перезаписать всё это осознанно:
`claude-dev-ctl retrofit dev-<имя> --force`.

Запись `Host omv 192.168.0.100` в ssh-config совпадает и с алиасом, и с IP: docker CLI
ходит по IP, а не по алиасу, и без этого падал с `Host key verification failed`.
Запись `Host github.com` обязательна, потому что ssh пробует только стандартные имена
ключей — `id_github` таким не является, и git молча упирался в `publickey denied`.

## Правила для Claude

Живут в `CLAUDE.md.template`, засеваются в `~/.claude/CLAUDE.md` каждого контейнера
(`__CONTAINER__` подставляется). Коротко:

- **Язык:** общение по-русски, всё в репозитории — по-английски.
- **Границы сред:** прод не трогать без разрешения, ничего не удалять, тома не трогать.
- **Git:** коммитить свободно, `push` — только с разрешения, в `main` напрямую не пушить.
- **Секреты:** ключи и токены в `$HOME` не читать и не коммитить.
- **Проверка:** «готово» = запущены тесты/линтер, результат показан.
- **Живучесть:** долгие процессы в `tmux`, не завязывать на ssh-канал.
- **Ревью:** внешнюю фазу ревью в ralphex делает `codex`; молча отключать её нельзя.

## Как менять состав

```bash
# 1. правишь Dockerfile / шаблоны в этом каталоге
# 2. синхронизируешь на хост и пересобираешь образ
scp Dockerfile entrypoint.sh arcane \
    CLAUDE.md.template codex-config.toml.template ralphex-config.template \
    omv:/root/claude-dev-build/
scp tui/claude-dev-ctl omv:/usr/local/bin/claude-dev-ctl
ssh omv 'cd /root/claude-dev-build && docker build -t omv/claude-dev:latest .'

# 3. правила, креды и настройки — сразу в существующие контейнеры
ssh omv claude-dev-ctl retrofit dev-<имя>
```

Новые инструменты из образа приезжают только в **новые** контейнеры: `retrofit` обновляет
настройки и секреты, но не пересобирает контейнер. Существующий контейнер получит их
после пересоздания (тома с кодом и логином переживут).
